## 実装した変更

初期表示は「起動」「RPC」「プール」の3つを中心にし、残り8領域はその場で展開します。11領域それぞれで「何を確かめるか」、平易な役割、入力、結果、失敗・待ち、抜粋の限界を示し、同じページ内で実コードと対応する行ヒントを開けます。ファイル一覧の探索は追加操作へまとめました。

ブロックチェーンの用語補助とコードの読み方の補助は独立して切り替えられます。固定のペルソナ別ページへ振り分けず、必要な箇所で語句、行、記号を選んで補助を足せます。補助変更時に選択や下書きを維持します。未対応の原文範囲は、処理説明・行ヒントが未対応と表示します。

7つの原文抜粋を追加し、計24文脈・96行ヒントを固定コミットに照合しました。特に、通信の`for`は反復と実装宣言を区別し、ストレージのコミットでストアをまたぐ原子性を断定しない、拡張への送信成功を拡張処理の完了と扱わない、ブロック候補の入口を内部アルゴリズム全体の説明と扱わない、といった境界も明示しています。

## 検証と再実行

ローカルの自動検査40件、静的画面の3検査群、原文照合、生成物の再生成一致を確認しました。静的画面では領域の入口から実行コード、選択行、記号ヒントを実操作で確認しました。33課題の操作評価はローカルアプリに対するものです。実ノードの同期・送信、外部AI連携、モバイル、人間による理解検証の合格を意味しません。

```sh
npm --prefix local-app test
node scripts/check-reading-data.mjs
npm --prefix local-app run req:trace
npm --prefix local-app run measure:strict
```

最後の厳密判定は、未達があるため終了コード2を返すことまで確認しています。通常計測の終了コード0は計算の成功だけを示します。UIが変わると古い評価の版ハッシュは一致せず、同じ版での連続合格として再利用されません。

採点可能な記録は`evaluations/reading-loop/`、詳細な方法は`docs/measurement.md`、現在値は`docs/reading-status.md`です。画面・操作の生ログは元ワークスペースの`outputs/measured-loop/`に保存し、リポジトリには評価に必要な匿名化済み記録を格納しました。
