# 学習の目的と画面の整理

2026-10-24。

## 目指す体験

コードリーディングを通じて、Rethの実装と、その前提になるブロックチェーン・Ethereum・RPCノードの仕組みを理解する。ブロックチェーンの知識を前提にしない。Rustの構文は、その処理を読む必要が生じたところで補足する。

一度に全リポジトリを把握するのではなく、一つの問いについて、説明とコードを往復できることを目指す。最初の問いは「署名済みの送信要求は、どこで受け取られ、何が返るか」。起動の読み方にもつなげる。

## 何が分かりにくかったか

既存の入口は、起動・構造・送信経路・Rust・ファイル・説明資料という機能の一覧だった。どれも読むための道具であり、何を理解してから何へ進むかを示していなかった。全体像を扱う複数画面、二重の見方の切り替え、読解段階のサイドバーが競合し、コードを読む前からメモ・書き出し・発表の操作も並んでいた。

## 入口と読む順番

主な入口は「学ぶ」「コードを調べる」の2つ。

学ぶ画面では、現在の出発点に合う読みどころと、一つの主な進行操作を示す。目次は必要なときに開く。文章は問い、目的、説明用の図、本文、言葉の補足、振り返り、次の読みどころで構成する。

1. ブロックチェーンとは？ — 記録と、その記録を検証する参加者。
2. Ethereumでは何を記録する？ — 状態と、署名された処理の要求。
3. ノードとRPCの役割 — アプリの窓口と、ノード同士の通信。
4. Rethは何を担当する？ — 実行側とコンセンサス側の分担。
5. 送信された要求を追う — 復元、要求の受け渡し、検証、プール追加、応答。
6. ノードはどう動き始める？ — 起動の準備と、稼働中の処理。
7. 疑問を持ってコードを読む — 日本語の説明、Rustの補足、根拠コードの往復。

5と6から既存の実装解説へ進める。7では、最初のRPC入口の説明を勧める。基礎説明だけを読ませて終わらず、コードを確かめるところまで結ぶ。

## 読み手に応じた表示

| 自分で選ぶ読み方 | 最初のおすすめ | 基礎説明 | 実装解説 |
| --- | --- | --- | --- |
| 基礎から学ぶ（初期値） | ブロックチェーン | 用語を開いて表示 | 日本語の役割・入出力を先に表示。型名・分岐・配置は必要なときに開く |
| ブロックチェーンの基礎はわかる | Rethの担当 | 用語は折りたたむ | 構造・送信経路・Rustを切り替えられる |
| コードを中心に読む | コードの読み方 | 根拠資料を開いて表示 | 詳細を表示。静的コード画面では手順一覧も表示 |

読み方は途中でも変更できる。基礎の説明はどの読み方でも開ける。自動的に理解度や経験を判定しない。

読み方、最後に開いた説明、自分で付けた「読んだ」の記録だけをブラウザーに保存する。読み方ごとに続きの位置を保つ。「読んだ」は理解の認定ではなく、取り消せる。保存が使えなくても説明は読める。読解メモは従来どおりローカルサーバー側に保存し、この学習記録とは別に扱う。

## 既存機能の置き場所

| 機能 | 整理後の位置 |
| --- | --- |
| 構造・送信経路・Rust | 読んでいる動作の説明から、必要な見方や補足を開く |
| 起動ガイド | 「ノードはどう動き始める？」から進む |
| 領域・モジュールの探索 | 「コードを調べる」。静的版ではexplore.html |
| ファイル名・パスの検索 | ローカル版の「資料・道具」→「ファイル名から探す」 |
| メモ・書き出し・発表 | コード画面の「読解ツール」。範囲のメモ欄も折りたたむ |
| 説明・印刷資料 | 「資料・道具」。学習の開始画面と区別する |
| 全体の処理図 | 静的コード画面で必要なときに展開する |

ローカル版の`/`は学習、`/reader`は従来の読解ワークスペースとする。古い`/#lens=...`や`/#path=...`は対象を保って`/reader`へ転送する。静的版の`index.html`は学習、`explore.html`は従来のAtlas。従来のファイル指定リンクも探索へ転送する。

## 説明の根拠と区別

基礎説明は[ethereum.orgの技術入門](https://ethereum.org/en/developers/docs/intro-to-ethereum/)、[トランザクション](https://ethereum.org/en/developers/docs/transactions/)、[JSON-RPC](https://ethereum.org/en/developers/docs/apis/json-rpc/)、[ノードの構成](https://ethereum.org/en/developers/docs/nodes-and-clients/node-architecture/)、[Rethの概要](https://reth.rs/overview/)を参照した。各基礎ページに詳しく読むためのリンクを置く。

Reth固有の送信・起動の説明は、既存のv2.7.0固定コードと照合する。上流資料の現在版と、読むコードの固定版を同一視しない。概念図は呼び出し解析・実行トレースとして示さない。

特に、キューへの送信、プールへの追加、ブロックへの取り込み、履歴の確定を区別する。実行の妥当性を検証するRethと、履歴を選び確定を追うコンセンサス側も区別する。

## 確認基準

- 初回は予備知識を要求せず、最初の説明に一つの主操作で進める。
- 7つの説明を順に読み、対応する実装解説とコードへ進める。
- 出発点を変えると、おすすめ、用語の開閉、実装解説の詳しさが変わる。
- 別の読み方を選んでも、元の読み方の続きや記録を失わない。
- 実コードから同じ処理の説明へ戻り、読んでいた基礎説明にも戻れる。
- 既存の範囲指定、メモ保存、ファイル探索、起動の説明を引き続き使える。
- 狭い画面で主操作、図、本文が欠けず、ページ全体が横にはみ出さない。

利用者による学習効果・読みやすさの受け入れは未確認。今回の実装とエージェントによる画面確認は、その代わりにはしない。
