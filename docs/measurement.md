# Reth読解の完了条件と計測方法

Reth全体を学べる状態と、一部の入口を使える状態を別々に判定します。完了条件は`requirements.json`、現在値は自動生成する`reading-status.md`と`reading-status.json`、全ファイルの状態は`coverage-ledger.json`に記録します。全体は全条件が達成されたときだけ完了です。

## 対象と母数

対象は`reading-target.json`に固定したReth v2.7.0のGitコミットです。全追跡blob 1,872ファイルを台帳へ記録し、そのうちRustの1,283ファイルを学習対象の母数にします。テスト、ベンチマーク、利用例も除外しません。Rust以外は補助ファイルとして明示します。外部依存クレートやマクロを展開した後のコードは、このGitツリーの母数には含みません。

ファイルの分類はパスに基づきます。分類済み、表示可能、抜粋に解説あり、全体をレビュー済みは異なる状態です。一つの抜粋があるだけで、そのファイルや所属領域全体を解説済みとは数えません。関数・分岐の全数に対する網羅率は、現状では未計測です。

原文照合の成功は、説明の意味の正しさまで保証しません。`impl … for …`を反復として説明した誤りは、原文照合が通っていても操作評価で発見されました。文脈別の回帰検査と、回答の原文照合を別に行います。

## 操作評価の規則

Aはブロックチェーンもコードも初めて、Bは他言語の開発経験がありブロックチェーンとRustは初めて、Cはブロックチェーンの基本用語は分かりコードを読むのは初めて、と置きます。課題の全文と順番は`requirements.json`の`evaluation.tasks`に固定しています。

各課題はホームから「コードを調べる」へ進む操作から数えます。ナビゲーション、展開、行・記号の選択、検索入力は各1操作です。課題間のホームへの復帰と、採点外の保持・回帰検査は分けます。誤クリックも含めて8操作以内に、対応する原文とその場の補助へ到達し、役割・入力・結果・失敗や待ちまたは範囲の限界を記録します。初期設定は課題の前に行います。

評価者は実UIだけを操作し、実装・設計・解答を事前に読みません。原文に対応する4事実は主担当が固定ソースと照合します。専門知識による穴埋め、原文に到達しただけの成功、未計測課題の成功扱いは認めません。生ログ、失敗、誤操作、無効な試行を保持し、再試行は元の成功へ繰り上げません。

`source-adjudication.json`は、各ペルソナと課題について、4事実の根拠、課題との対応、未解決の進行阻害数、照合者を記録します。生ログの`blockers`配列には回復した迷いや誤操作も含まれるため、未解決の進行阻害数を明示して0を要求します。この区別を全ての回へ同じように適用します。

同じ3者による再評価なので、初見の発見性や独立した学習効果の試験ではありません。AIの回答が画面と合うことを、人間の理解成立と扱いません。所要時間や架空の理解率も作りません。

## 計測コマンド

プロジェクトルートから実行します。

```sh
node scripts/measure-reading.mjs
npm --prefix local-app run req:trace
npm --prefix local-app run measure:strict
```

通常の計測は結果をJSONとMarkdownへ保存します。計測処理の成功と、全体の完了を区別します。`--require-complete`または`measure:strict`は、全体が未達なら終了コード2を返します。自動テストが通っても、完了判定を成功へ書き換えません。

```sh
node scripts/measure-reading.mjs --evidence /absolute/path/to/round --output /absolute/path/to/report
```

明示した評価結果は、条件のハッシュと、UI資産・APIソース・対象設定のハッシュが一致しなければ拒否します。既定では`evaluations/reading-loop/latest.json`が示す互換のある記録を使用します。コードを変えて互換がなくなった場合、古い評価を新しいコードの達成として流用しません。成功が連続した回数は、直前の記録も同じ修正版の場合だけ増やします。

`req:trace`は計測した達成状態と、要件IDが付いた検査ファイルを要件へ反映し、台帳と達成状況を再生成します。要件の本文・母数・しきい値は変更しません。生成結果を確認してコミットします。

## 全体レビューの記録

`ui/full-file-reviews.json`は任意の手動レビュー記録です。未作成は0件として扱います。各記録には`path`、`commit`、全文の`sourceHash`、`reviewer`、`scope: "whole-file"`、`allItemsChecked: true`、`operations`、`branches`を必要とします。分岐や実行時の処理を持たないファイルも、確認して「なし」と記録し、母数から除外しません。見出しや抜粋だけの確認を全体レビューとして記録しません。

これは確認記録の数であり、AST解析によって全関数・分岐の網羅を証明した数ではありません。未確認の記録を自動生成で埋めることも認めません。

## 人間の理解検証の記録

評価ディレクトリの`human-study.json`を読みます。`kind: "human-observation"`、実観察の記録者`attestedBy`、対象`commit`、`policyHash`、`buildHash`と、`participants`を記録します。参加者はペルソナごとに1人、匿名の`pseudonym`、`kind: "human"`、観察者`observedBy`、11課題の`tasks`を持ちます。

各課題は`id`、`helpClosed: true`、原文の`source`、`answers`の4項目、`rubric`の4項目の0/1採点、`sourceSupported: true`、`criticalMisconceptions: 0`を記録します。原文パスと行範囲も照合します。実際の観察を行った人の記録を用い、AIのペルソナ出力からこのファイルを作りません。未実施は未確認のまま残します。
